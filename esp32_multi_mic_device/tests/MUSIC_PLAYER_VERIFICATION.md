# 完整播放器验证

生产代码的主机回归入口：

- `music_host/run.ps1`：768 KiB 环形缓存的随机生产/消费/环绕/部分输出；暂停、嵌套前台任务、陈旧下载代际和超过 32 位的进度；79 tap FIR 的通带、10/18 kHz 抗混叠和跨块连续性。
- 同一入口编译真实 `full_music_player.cpp`，仅模拟网络/I2S/RTOS：未知 Content-Length、127 字节奇数 TLS 分段、available 空隙和负读取、缓存满时取消、取消后的陈旧包、偏早 EOF、JSON 截断、中文歌词/下一句、独立音频输出、4 秒预缓冲 / 断流恢复、目录查询不抢音频、低内存 / 碎片化内存阻止第二条 TLS、TLS 分配器内存选择 / 溢出 / 清零 / 失败回退 / 无 PSRAM、前台资源交接及恢复 16 kHz。
- `voice_capture_host/run.ps1`：真实 `voice_input.cpp` 的双 I2S 48/16 kHz 切换、MIC3 3:1 降采样、实际 10 kHz 抗混叠、录音的采样率保护、I2S 部分写入、时钟切换失败恢复及全部既有收音回归。
- `node tests/music_ui.mjs`：生产网页脚本的模拟 100 MiB XHR 直传、一次性票据、已有音乐补 LRC、安全 textContent、分页/歌单/控制、ID3 自动标题不被文件名覆盖，费用曲线随筛选使用 `cost_chart`。
- `display_host/run.ps1`：生产屏幕渲染器和真实字体，新增音乐页覆盖两种屏幕共八个方向；既有相册/语音/表情/配置二维码渲染继续回归。

主机测试不能验证真实网络 TLS 时序、麦克风/功放接线、扬声器音质、声学回声下的唤醒率或实际 OLED/LCD 可读性。发布前需编译完整 ESP32 固件并实机验证播放、歌词、暂停/恢复、唤醒进入对话、短铃声试听、闹钟及 OTA 的资源交接。

2026-10-03 完整编译与 COM4 USB 烧录通过，模型 SHA-256 验证通过；实机 48 kHz 音乐与歌词状态、暂停 / 恢复及原配置保留已验证。人工持续播放和歌词同步待用户确认，其他实机验收以 `docs/音乐播放器测试文档.md` 的发布范围为准。

2.1.1 回归：8,046,061 项环形缓存 / 意愿 / FIR / 预缓冲检查，12,382 项生产播放器检查通过。监听任务在读取间隙的状态由持续启用标志恢复，前台持有音频时输出任务不得改变功放 / 时钟。网页生产脚本直传与费用筛选回归通过。实机最终记录见使用与测试文档。

用户实机反馈（2026-10-03，2.1.1）：持续播放基本无卡顿，初始缓冲稍长暂缓处理；持续播放时仍不能可靠唤醒，切歌的安静间隙可以唤醒。监听启用状态不能作为真实声学唤醒通过的证据。
