# 多麦克风工程验证记录

日期：2026-10-02。

## Windows 主机测试

命令：`tests/voice_capture_host/run.ps1`。其中生产 TLS 音频下载辅助函数额外通过 45 项检查：记录间暂时无数据、短读取、空读取重试、字节/边界一致、总时限、部分下载计数、取消与时间回绕。实际编译 `voice_input.cpp` 与 `multi_mic_config.cpp`，通过 **734 项检查**。I2S、NS/VAD、NVS、时间和存储由模拟实现提供。

验证范围包括原单麦克风降噪/VAD、录音和上传缓冲、手动/按键/免按键结束、取消、存储错误、PSRAM 分配失败及对话流程；新增覆盖：

- 默认只启用 MIC1，未安装接口的信号不参与选择，I2S1 不启动。
- MIC2 单独接入使用右槽，MIC3 单独接入使用第二控制器左槽。
- 双麦克风、三麦克风以及 MIC1+MIC3 组合。
- auto 的持续强度判断及切换保持，固定通道录音及离线唤醒输入。
- 从离线监听进入录音前清理缓冲，保留监听选出的麦克风。
- 文档 GPIO 对照、短读取补足、非法帧拒绝、MIC3 初始化失败回退、读取失败不保留可上传音频。
- 两组控制器释放和恢复、禁用 MIC3 关闭 I2S1、采集期间禁止改配置。
- 串口命令解析、安装掩码校验、NVS 配置恢复、损坏配置回默认与写入失败反馈。
- 诊断采集不写音频文件。
- 多路模式启用前需真实变化信号，静音/固定直流/削波未通过时恢复原配置、不保存 NVS。
- NVS 写入失败恢复原掩码和固定通道；收音期间冻结通道。
- 待机底噪校准，自动换通道后丢弃旧基线并重新校准，模式更换后清除旧基线和网页快照。
- 采集持有麦克风锁时状态查询仍读取非阻塞的原子快照，超过 30 秒未更新的基线停止参与语音门槛。
- 新麦克风网页的实际 JavaScript 验证重复请求保护、固定通道限制及失败后的模式恢复。

功能同步后的主机检查另覆盖：自定义唤醒 1,591 项，离线模型缺失/存在分别 17/22 项，番茄钟 234 项与网页 25 项、个人记忆、动作互动 704 项及网页流程、收音设置 270 项，提醒命令及贪睡存储与 PageStream 页面 50 项。全部通过。

## 实物范围

主代理已通过 COM4 USB 烧录 2.0.0，并通过云端铃声下载播放、响铃时保持离线唤醒监听、网页贪睡与停止检查；原铃声恢复，测试提醒删除。当前实物仅确认默认 MIC1。实际麦克风针序、供电、左右声道、两组时钟漂移、机械安装、底噪与 DMA 丢帧需要接线后验证。软件检查不代表实际阵列同步，不包含声源定位或波束形成测试。
