# ESP32-S3 多麦克风工程（兼容单麦克风）

多麦克风主维护工程，版本 2.1.2，支持完整音乐播放器及 LRC 歌词。入口为同名 `esp32_multi_mic_device.ino`，在 Arduino IDE 中打开它即可。保留原来的云端对话、屏幕、四舵机、按钮、降噪、VAD、离线/自定义唤醒、个人记忆、番茄钟和互动动作等功能。单麦克风 1.4.4 保留兼容维护，新增功能以本工程为主。

默认只启用 MIC1，所以只装原来的一个麦克风即可运行。接入第二、第三只后，在网页收音页选择单/双/三麦克风或使用串口设置；程序不会根据 I2S 初始化成功判断有没有物理麦克风。启用多路需通过 1.5 秒信号检测，请对各只麦克风说话：每路原始 RMS 至少 8、峰值低于 32760 才通过。读取成功、静音、固定直流不算检测通过。检测失败或保存失败恢复原掩码和固定通道。信号检测用于接线验收，不能单凭它保证接口无串扰或完成方向判断。配置保存在独立的 `multi-mic` NVS 命名空间，重启仍有效。

网页“音乐与歌词”支持完整 MP3/WAV 音乐与 LRC 直传云端，也能给已有音乐补充歌词。完整播放器没有固定上传容量或时长门槛，容量受云端磁盘约束；上传不经过设备闪存。可搜索歌曲/歌手，创建、选择和编辑服务器歌单。新上传时歌名、歌手留空可由云端识别标签，手动填写可覆盖。

服务器保留原始音乐，设备播放连续 48 kHz / 16 bit / 单声道 PCM；当前功放为单声道。设备只保留 768 KiB PSRAM 环形缓存，未知长度歌曲按真实流结束判断末尾，时长用于进度估计。下载与输出是独立任务；输出优先于 TLS 下载，WakeNet 使用另一 CPU 核。起播与断流恢复预缓冲 4 秒，短歌真实 EOF 可提前输出；浏览目录时，TLS 4 KiB 以上分配优先使用 PSRAM；内部空闲内存至少 40 KiB 且最大连续块至少 12 KiB 才允许短 HTTPS 查询与音乐流共存；内存不足则先补足 6 秒缓存再串行查询，10 秒补不满会提示稍后重试，保持音乐继续。音乐期间后台资料同步延后至空闲。采样率切换按监听任务的持续启用状态恢复唤醒。下载偏早中断时暂停并提示重试，继续播放保留缓冲和偶数字节恢复位置。

音乐播放期间，RX DMA 将三路麦克风与实际完成输出的 TX DMA 参考音频配对，使用相同 FIR 转成 16 kHz 后进行 ESP-SR SR_HIGH_PERF 回声消除，最后才加唤醒增益。参考来自当前音量下的实际输出，功放静音时置零；处理不改变播放音质或插入静音窗口。第三麦克风仍为通道选择，两组时钟不用于定位。`/status` 提供 `music_echo_*` 输入 / 参考 / 输出 RMS、处理帧、丢帧和耗时。实机人声唤醒效果须另行验收；不可把 active 状态当作识别成功。

播放器与麦克风共用第一组 BCLK/WS，播放音乐时两组 I2S 均运行在 48 kHz，麦克风通过持续 FIR 滤波和 3:1 降采样输出 16 kHz 给离线唤醒。对话、闹钟、声音训练、麦克风检测及 OTA 开始前，先等待音乐 TLS 关闭，再恢复 16 kHz；结束后恢复用户的播放意愿。暂停/停止指令不会被后台任务恢复覆盖。歌词依据成功提交到 I2S 的样本数更新，可能有少量 DMA 播放延迟；声学回声及唤醒识别效果需实机检查。

常用语音：“播放强军战歌”“播放阎维文的歌”“上一首”“下一首”“暂停音乐”“继续播放”“停止音乐”“音量调到百分之三十”“调大音量”“调小音量”。音量与语音共用，明确调整会切换到固定音量并保存；上下调整每次 10%，范围 0～100。播放时仍可说唤醒词进入对话。播放状态及当前/下一句歌词也可在网页控制；待机屏幕显示歌曲和歌词，番茄钟页面保留原显示优先级。

闹钟页的短铃声上传仍保留 20 MB 源文件与前 15 秒截取，独立于完整播放器；管理员短铃声截取前 30 秒。支持试听当前选定铃声，试听不会创建闹钟或修改音乐队列。

闹钟支持云端铃声选择、循环播放、响铃时语音唤醒后关闭或稍后提醒；音乐加载失败使用提示音。待机自动校准环境底噪，收音时冻结基线，网页显示背景偏吵、声音偏小或增益过高等建议。费用以简表和随所选统计周期自动汇总的价格曲线展示。

## 接线

| 麦克风 | VDD | GND | SCK/BCLK | WS | SD | L/R |
| --- | --- | --- | ---: | ---: | ---: | --- |
| MIC1 | 3V3 | GND | 42 | 41 | 21 | GND，左声道 |
| MIC2 | 3V3 | GND | 42 | 41 | 21 | 3V3，右声道 |
| MIC3 | 3V3 | GND | 18 | 38 | 11 | GND，左声道 |

表中数字都是 GPIO 编号。MIC1/MIC2 共用数据线的前提是 L/R 一左一右。MIC3 的时钟、数据不能与第一组并接。功放仍使用 BCLK42、LRC41、DIN40、SD/EN39；其余屏幕、四舵机、按键引脚保持原接线。

完整资料：[逐针接线与走线](docs/接线方案.md)、[详细接线图](docs/详细接线图.svg)、[基础单麦克风接线](docs/单麦克风原接线.md)。

## 安装数量和录音模式

串口波特率 **460800**，命令末尾发送换行。在录音、播放或更新结束后设置。

| 命令 | 作用 |
| --- | --- |
| `/mic` | 查看安装掩码、模式、当前通道和各通道 RMS/峰值 |
| `/mic count 1` | 只启用 MIC1；默认配置 |
| `/mic count 2` | 启用 MIC1 + MIC2 |
| `/mic count 3` | 启用 MIC1 + MIC2 + MIC3 |
| `/mic select auto` | 在已安装通道中选择持续更强的通道 |
| `/mic select 1` / `2` / `3` | 固定使用指定通道；必须已启用 |
| `/mic mask 1..7` | 任意组合，见下表；同时回到 auto |
| `/mic test` | 采集约 500ms 做本机诊断，打印各路平均 RMS 和最大峰值，不上传或保存音频 |

`count` 也会重置为 auto。只接一只时 auto 始终使用这只，不会读取第三组总线。只接 MIC2 或 MIC3 也可通过掩码使用。

| 掩码 | 安装组合 |
| ---: | --- |
| 1 | MIC1 |
| 2 | MIC2 |
| 3 | MIC1 + MIC2 |
| 4 | MIC3 |
| 5 | MIC1 + MIC3 |
| 6 | MIC2 + MIC3 |
| 7 | 三只全部 |

例如只接第一和第三只：`/mic mask 5`；只测试第三只：先 `/mic mask 4`，再 `/mic test`。

auto 使用去除直流后的原始 RMS 判断，候选通道至少达到 32、且超过当前通道约 1.8 倍并持续 250ms 才切换；遇到差不多的音量会保持当前通道。它是音量选择策略，无法区分讲话、扬声器声音或电机噪声，首词可能先由原通道采集；需要稳定对比时用固定通道。待机和离线唤醒允许自动选路；开始收音后冻结通道，整段录音不切换。录音和离线唤醒都使用同一选路入口，上传仍为 16kHz / 16bit 单声道 PCM，现有服务器不用改变音频格式。

三只会被读取并计算各路诊断数据，输出选择其中一路。两组独立 I2S 时钟不保证逐样本同步，本版本没有波束形成、方向定位或多路原始文件导出。启用但未接的接口不能保证读到零，请按真实接线配置。

## 编译和首次使用

Arduino ESP32 开发板包：本次使用 **3.3.12**。开发板选 ESP32S3 Dev Module，Flash 16MB、OPI PSRAM、ESP SR 16M 分区，USB CDC On Boot 关闭（对应外接 UART0）。改用原生 USB 串口时需把 CDCOnBoot 改成 cdc。

额外依赖：ArduinoJson、Adafruit GFX、Adafruit ST7735 and ST7789、U8g2_for_Adafruit_GFX。I2S、LEDC 舵机控制、ESP-SR 和 qrcode 等由当前 ESP32 开发板包提供。

首次在新开发环境使用中文离线模型时运行 `install_offline_wake_models.ps1`；它会备份并替换开发板包的模型文件。然后执行：

```powershell
.\esp32_multi_mic_device\build.ps1
```

脚本查找 Arduino CLI，编译到本工程 `build/`，并检查分区、模型包和应用大小。也可指定 `-ArduinoCli` 和 `-LibrariesDirectory`。不会烧录或连接串口。

首次烧录使用 Arduino IDE/CLI 的完整上传，带 bootloader、分区和离线模型。保留本地 `secrets.h` 及原设备 NVS 的使用方式，设备网页配网流程不变。

本工程 OTA 硬件通道为 `esp32s3-cloud-voice-multimic-v1`，与单麦克风通道分开，避免单麦克风发布包覆盖本工程。首次完整安装使用 USB/UART；后续 OTA 必须按该硬件通道独立签名发布。
