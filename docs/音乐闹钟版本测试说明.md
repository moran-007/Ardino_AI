# 音乐播放器之前的版本：测试与恢复

版本：单麦克风 1.4.4、多麦克风 2.0.0；日期：2026-10-02。

## 已完成验证

两个工程均使用 ESP32 Arduino 3.3.12、16 MB Flash、OPI PSRAM、ESP SR 16M 分区完成编译，应用镜像分别为 2,372,256 和 2,384,544 字节；中文唤醒模型 3,784,096 字节，地址 0xC10000。两组 OTA 硬件通道独立，不能交叉升级。

服务器完整回归 163 项通过，费用筛选相关 15 项通过。单麦克风录音主机检查 375 项、多麦克风 734 项；TLS 分段下载 45 项、提醒 50 项及原有唤醒、记忆、番茄钟、互动和设置检查通过。

费用曲线跟随上方筛选：近 24 小时按小时，近 7/30 天按天，累计按数据跨度自动选择粒度。无调用显示零；未计价保留缺口；不同币种不合并换算。

## 实机复测步骤

1. 打开设备网页，确认版本、音频初始化和离线唤醒就绪。
2. 在提醒区域确认“当前铃声”显示歌曲标题，读取铃声列表并保存一首。
3. 建立两秒倒计时，确认扬声器播放云端铃声；响铃期间网页仍可操作，离线唤醒保持监听。
4. 点击延后和停止，确认响铃结束；删除本次测试提醒并恢复原铃声。
5. 用真实语音唤醒，说“停止闹钟”“再等三分钟”，检查实际播报和提醒时间。
6. 待机重新校准底噪，观察背景噪声和提示；讲话收音期间基线应冻结。
7. 多麦克风默认使用 MIC1。实际接好其他麦克风后，网页选择多路并完成检测；缺失、静音、固定直流或削波信号应拒绝启用。
8. 检查便签、待办、个人记忆、照片、番茄钟、舵机、对话及 OTA 的既有入口。

自动实机检查使用网页建立短计时器，确认云端铃声加载、响铃期间唤醒监听、贪睡和停止；完成后恢复原选择并只删除测试创建的提醒。实际人声识别、音质和多只物理麦克风仍需上述人工步骤，不由主机模拟测试代替。

## 上传限制

本版为短铃声功能：服务器 MP3 源文件最多 20 MB，保留前 30 秒；设备网页浏览器解码源文件最多 20 MB，截取前 15 秒转为 16 kHz WAV，临时转传最多 512000 字节。该限制不适用于后续完整音乐播放器。

## 恢复

音乐播放器之前的源码和固件保存在独立 ZIP 与 Git 分支。完整首次烧录必须同时使用正确的分区表、应用和中文模型，推荐 Arduino CLI/IDE 上传，不能只写应用镜像；常规 OTA 保留现有分区、照片和 NVS 设置。签名私钥不包含在归档中。
