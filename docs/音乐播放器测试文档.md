# 音乐播放器使用与测试

主工程：`esp32_multi_mic_device`，版本 2.1.0。单麦克风 1.4.4、多麦克风 2.0.0 是播放器之前的留存版本。两个工程与服务器代码均保存在 GitHub 对应分支。

## 使用

设备连接 Wi-Fi 后打开设备网页并登录，进入“音乐与歌词”。点击“全部歌曲”，选择歌曲播放；也可按歌曲名或歌手搜索。提供上一首、下一首、暂停、继续、停止和共享音量。屏幕与网页显示歌曲、歌手、实际播放进度、当前与下一句歌词。

上传完整歌曲时选择 MP3/WAV，可同时选择 LRC；歌曲名、歌手留空由服务器识别，手动填写覆盖识别结果。也可选自己的已有歌曲补歌词。音乐通过浏览器直接传云端，不在 ESP32 保存整首文件，不受短铃声的 20 MB 或 15/30 秒限制。实际限制为服务器剩余空间、网络与处理能力；歌词最多 1 MB。取消或失败后重新上传，不支持断点续传上传。

服务器歌单可以创建、加入歌曲、移除歌曲和删除；选择一个歌单后，上下曲按歌单顺序循环。“全部歌曲”使用可访问音乐库顺序。用户私有歌曲只能由该设备和管理员查看，管理员 `/admin/music` 可查看全部歌曲、歌词和用户歌单，并上传共用歌曲。

语音先用已有唤醒词唤醒助手，可说：

| 指令示例 | 预期行为 |
| --- | --- |
| 播放音乐 | 继续当前歌曲，或从音乐库开始 |
| 播放强军战歌 / 播放阎维文的歌 | 搜索库中的歌名或歌手并播放 |
| 上一曲 / 上一首 | 切换上一首 |
| 下一曲 / 下一首 | 切换下一首 |
| 暂停音乐 / 暂停播放 | 暂停，进度不再增加 |
| 继续播放 / 恢复播放 | 保留缓冲与实际播放位置继续 |
| 停止音乐 / 关闭音乐 | 停止并释放当前播放队列 |
| 音量百分之三十 / 调大音量 / 调小音量 | 设置音量或以 10% 调整，保存为固定音量 |
| 当前音量多少 | 播报当前有效音量 |

闹钟设置区域显示当前已选铃声；试听及停止试听保留铃声选择，不建立真正的闹钟。闹钟、对话、TTS、麦克风检测和 OTA 抢占音乐，结束后按用户播放意愿恢复；用户已暂停或停止时不能自动重新播放。

## 音频与限制

音乐使用 48 kHz / 16 位 / 单声道 PCM，单喇叭不输出立体声；语音和铃声继续 16 kHz。设备 PSRAM 音乐缓冲固定 192 KiB，歌词按实际成功输出的采样数定位。服务器保存 MP3 原件，播放时连续解码，不存完整 PCM 副本、不再有损压缩；网络约 96 KB/s，即约 346 MB/小时。原音频质量、喇叭、供电和网络仍影响实际听感。

服务器最多四路同时解码，同一设备一条；磁盘写入保留约 256 MB 余量，歌曲数量没有人为上限。当前未实现设备 MP3 解码、离线完整音乐存储、上传断点续传、随机播放、收藏、睡眠定时、AEC 或声源方向判断。建议见 [后续增强](音乐播放器后续规划.md)。

## 复现命令与恢复

服务器：在项目根目录运行 `python -m unittest discover -s cloud_server/tests -q`，安装 FFmpeg/FFprobe 的部署主机应运行真实音频检查，不能把 Windows 跳过真实音频工具的结果当作其通过。

设备：运行工程 `tests/music_host/run.ps1`、`tests/voice_capture_host/run.ps1` 及相关网页 / 屏幕检查，然后使用 `build.ps1` 完整编译与模型检查。FQBN 为 `esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=default,FlashSize=16M,PartitionScheme=esp_sr_16,PSRAM=opi`。

完整首次烧录使用 Arduino CLI/IDE，包含分区、应用及地址 0xC10000 的中文模型；应用 OTA 只能用于已有兼容分区，单 / 多硬件通道不可混刷。播放器之前的完整 ZIP 保存在本机 `release_archives/pre_music_player_complete_20261002.zip`，源码 ZIP 为同目录 `pre_music_player_sources_20261002.zip`。完整归档可能包含设备配置写入的固件，因此不放在公开 GitHub，签名私钥也不包含在归档中。
