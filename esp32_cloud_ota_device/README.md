## 1.4.4：单麦克风最后一版功能对齐

后续新功能以 `../esp32_multi_mic_device/` 为主，单麦克风工程保留兼容与维护。多麦克风工程默认启用一只麦克风，可以沿用现有接线；新增通道须在网页检测通过后启用。

本版加入云端音乐闹钟和设备网页音乐上传。响铃时继续监听唤醒词，唤醒后暂停音乐，说“停止闹钟”“结束闹钟”或“再等三分钟”；不带时间的稍后提醒默认五分钟。断网或下载失败使用本机提示音，中断键停止、说话键延后五分钟、十分钟自动结束仍保留。

设备网页可选择云端铃声、停止或延后闹钟、上传 MP3 等浏览器可解码的音频。源文件最多 20 MB，浏览器截取前 15 秒并转为 16 kHz、16 位单声道 WAV，设备分块写临时文件转传云端后删除，最大转传 512000 字节。音乐库总上限 12 首（含三首原创示例），设备各自最多上传 6 首私有铃声；管理员上传共用铃声，支持最多 20 MB 的 MP3（截取前 30 秒），或最多 1 MB / 30 秒的 16 kHz PCM WAV。

`music_player.cpp/.h` 用 PSRAM 缓存一段有上限的闹钟铃声（最多 1 MiB），以 100 毫秒音频块循环播放，主循环继续处理网页和控制，麦克风监听保持原 16 kHz 时钟。此版不是完整歌曲播放器，长曲流式 MP3 和高采样率方案见 [后续建议](../docs/音乐播放器后续规划.md)。

待机自动估计背景噪声的低四分位基线，录音和响铃冻结基线。录音同时通过原有 VAD、固定能量门槛和按增益计算的环境能量门槛；网页显示底噪、门槛及“背景偏吵／声音偏小／增益过高”，支持重新校准。数值为数字采样幅度，不是声压或 dB SPL。

费用页面显示日期、用量、调用时单价和总价格，提供日／周／月费用曲线，保留币种分离及未计价提示。

## 1.4.3 唤醒恢复与录音提前退出修复

当前对话的写盘延迟优化：唤醒、按键、网页手动三种入口都直接上传已有 PSRAM 中的 PCM，不再先写临时 Flash 文件再读回。没有新增一份音频复制；25 秒最多占用 800 KB PSRAM，上传和原有的连接前失败重试期间保留，上传返回后、等待回答前释放，其他提前退出由作用域清理。新一轮录音先清除前一条，无有效语音或取消不上传旧数据。`recorded` 日志显示“PSRAM直传”，`recording_backend` 为 `PSRAM`，`StorageMs` 正常应为 0；`AudioStats.fileBytes` 保留兼容字段名，但表示本轮可上传的 PCM 字节数。历史记录、照片、配置、唤醒模型及分区不变；服务器仍只覆盖保留最新一条诊断 WAV。旧文件录音接口作为兼容路径保留，不处理其偶发写入失败。本次不编译或上传 ESP32 固件，需用户安装后验证实际响应时延及 HTTP 上传。

后续重复唤醒排查：WakeNet 的 `WAKENET_CHANNEL_VERIFIED=-1` 只表示声道确认，不再作为新唤醒处理；仅 `WAKENET_DETECTED=1` 启动对话。真实重复检测/回声是否仍存在需实机核对，不恢复有崩溃风险的 `clean()`。设备最新成功样本的采集为 3424 ms、写盘为 6480 ms，说明回答前长等待至少部分发生在存储阶段。写盘失败日志新增 `Saved`、`Errno`、`StorageMs`，状态接口新增对应字段，保留部分写入进度但仍删除无效临时文件。错误码为 0 只表示底层未提供 errno，不能据此判定存储正常。本次不删除照片、不格式化、不缩短停顿设置，未编译或上传固件。

1.4.2 实机在录音退出后调用 WakeNet9 `clean()` 时出现 `LoadProhibited`，堆栈为 `dl_convq_queue_bzero → model_clean → OfflineWake::resume`。1.4.3 移除该调用，保留模型、唤醒检测、暂停同步和 240 毫秒麦克风缓冲清理。1.4.2 在服务器标记为撤回并保留归档。

针对后续“唤醒后约一秒录音无效，RMS=0、Peak=0”，源码移除网页处理超过 50 毫秒或累计处理耗时超过采样时长 50 毫秒就取消录音的判断；这些耗时包含正常降噪、文件写入和网页服务，不能直接判定 I2S 丢样。同一网页回调也不再仅因耗时取消播放。保留实际 I2S/文件读写失败、初始化失败、手动停止、语音检测和静音超时；录音失败时回填已采集的 RMS、Peak、Samples，并在运行日志显示具体失败原因，避免未回填的零值被误认为麦克风静音。

不改收音参数、降噪算法、连续对话偏好、分区表或模型包。本次录音修复按用户要求只改源码，未编译或上传 ESP32 固件；电脑侧回归已运行。需用户编译上传后验证正常问句、静音超时、反复唤醒及网页/实体停止。

网页 AI 当前对话及历史记录新增北京时间戳（年月日、时分秒）。用户消息记录本轮录音流程开始时间，AI 消息记录首次出现回答文字的时间；分段追加和网页刷新不更新时间。Unix 秒写入历史记录的 `user_at` / `assistant_at` 字段，原来的 `at_ms` 保留；旧记录显示“时间未记录”，设备尚未同步时间时显示“时间未同步”，不从开机时长推算历史日期。浏览器逻辑检查可运行 `node esp32_cloud_ota_device/tests/conversation_time_check.js`，不需要编译固件。

免按键收音在开始后一直没有有效语音时，也按“停顿发送”时长提前结束；检测到有效语音后的自然停顿结束行为保持不变。默认 8 秒现在仅是尚未确认有效语音时的最长等待上限，不要求每轮录满；无有效语音返回待机且不上传。保留最短录音时长、按键松开发送及手动中断，连续对话遇到静音也会结束本次会话。静音时长按音频采样计算，存储写入阻塞仍可能拉长实际等待时间，需要继续独立排查。

2026-10-01 的测试录音保存了 2.71 秒音频，但设备录音阶段用了约 6.515 秒；ASR 前半句正确，后半句出现明显偏差。为排查采集阻塞，当前源码将录音 PCM 先缓存在 PSRAM（25 秒上限最多 800 KB），停止收音后再写原来的临时文件，无语音时不写文件。分配失败明确报错，不回退到内部 RAM。增益、灵敏度、降噪强度和唤醒模型不变。`/status` 与 `recorded` 运行日志分别显示音频时长、采集、准备、写盘、网页、DSP 耗时及最大读取间隔；阶段总时长不能直接等同于丢失的音频时长。电脑侧测试证明慢写盘不再发生于采集循环，不能替代实机 DMA/语音识别验证。本次未编译或上传 ESP32 固件。

“语音与音量”页新增“开始收音”和“结束并发送”。开始请求经登录校验后排队，由主循环启动单轮录音，不依赖实体按钮；网页显示“收音中”后开始说话，点击结束会保存并走原识别流程。手动模式不按停顿自动结束，25 秒音频上限仍会结束并发送；没有有效语音则不上传。“结束当前对话”和实体中断键仍取消本轮，包括尚未开始的排队录音。手动测试不自动续录，也不修改已保存的连续对话开关；原来的唤醒、停顿自动发送及按键松开发送保持不变。

## 1.4.2 收音与连续对话

设备网页的“语音与音量”新增录音增益（1～12 倍）、收音灵敏度（0～100）、录音降噪、停顿发送（600～3000 毫秒）、等待说话（3～20 秒）与连续对话开关；保存到 NVS，重启和同分区 OTA 后保留。建议先用默认增益 5、灵敏度 50、降噪开启，依据最近录音的音量、峰值、有效语音时长与削波数微调；削波较多时降低增益。灵敏度只影响录音语音检测，不改变离线唤醒词阈值。

录音使用 ESP-SR 降噪与 VAD，结合能量和持续时间确认语音；无有效语音则丢弃音频，不请求云端回答。1.4.3 恢复唤醒前仅清理麦克风缓冲，不调用会导致崩溃的模型 `clean()`。免按键录音总长最多 25 秒音频（包含等待时间），与云端 800000 字节上限匹配。1.4.3 不再用网页耗时取消正常采集或播放；同步网页和网络请求仍可能使停止按钮响应延迟，新增分阶段耗时用于实机排查。

连续对话默认关闭。开启后，回答结束短暂停顿再收音，不限制为两轮；等待超时、出错、实体中断键或网页“结束当前对话”都会结束本次会话。结束不会关闭已保存的连续对话偏好，下次唤醒仍按该偏好工作。降噪不是声学回声消除，当前保持半双工，不能保证旁人说话或电视声音不会被识别。

本版本保持 1.4.1 的 ESP SR 16M 分区和模型包，只向 1.4.1 及以上来源版本提供应用 OTA；1.3.x 和 1.4.0 不能用此包代替首次 USB 分区迁移。云端 `/admin/firmware` 保留每个已归档版本的说明、时间、大小、校验值和签名 ZIP，已撤回版本只显示记录。

验证记录见 `tests/VOICE_CAPTURE_VERIFICATION.md`。主机测试与编译不代替实机声学验证；外壳开孔是否衰减语音，需要同位置、同音量的带壳/裸板录音对比，不能仅凭照片确定。

## 亮度、表情动作和说话显示（2026-09-29）

登录后台 → **屏幕与相册**，顶部可设置竖屏造型、亮度，以及按键说话、语音唤醒各自的显示方式。保存后即时应用，不需要重启；普通重启和同分区的应用 OTA 后保留。

- **亮度**：默认网页控制、100%，范围 5–100%。滑块选择数值后点击“应用并保存亮度”；或选择 GPIO1 电位器，旋钮实时调节且不会反复写入 Flash。ST7735S 的 BLK/GPIO16 使用 5 kHz 背光 PWM；7 针 M200T/ST7789 没有 BLK，使用 RGB565 软件压暗，不能降低背光本身的亮度或功耗。PWM 初始化或写入失败时回退到软件压暗。
- **电位器**：两端接 3V3/GND，滑臂接 GPIO1。这个输入只能供亮度、音量、电池检测之一使用。若原本用旋钮调音量，先在“语音与音量”改为固定音量，再启用亮度旋钮。网页和配置接口均校验冲突；开启电池检测的固件会禁用这两个旋钮模式。
- **表情与天气主页**：共用程序绘制的 **8 类、48 组**动态表情。按最新参考，默认横竖屏均为浅蓝发光眼睛与小嘴，配深蓝波浪底景；时间在上方、表情居中、天气在下方。竖屏不强制全身，可在“竖屏造型”切换为带头、身体、手脚的角色，展示挥手、拍手、比心、拥抱、托腮、伸懒腰、擦泪、跳舞等 18 类动作。不同原生尺寸分别排版，无需下载图片，也没有额外的全屏帧缓冲。参考图的 360×240/240×360 比例不改变已接屏幕的真实分辨率。
- **后台表情库**：独立导航入口，按开心互动、喜欢害羞、好奇思考、困倦放松、委屈难过、生气傲娇、惊讶紧张、搞怪庆祝分类，每类 6 组。支持搜索、发光表情/全身角色缩略图、勾选启停、批量选择、撤销修改和保存。至少启用一组，多组随机且避免连续重复；单组固定表情但继续播放动作。设备空闲时可预览任意表情 8 秒，按设备当前方向和造型显示，轮播暂停并在结束后回到原页面，也可提前结束。对话、闹钟、更新与配网优先于预览。缩略图由同一绘图代码生成，每次临时占用 18 KiB PSRAM，按需加载。
- **说话显示**：“按键说话”和“语音唤醒”各自选择“底部状态条”或“全屏表情与文字”，首次默认都为状态条。底部条在 ST7789 高 54 像素、ST7735S 高 32 像素，显示当前状态及一行自动翻页文字；保留当前页面，天气内容收紧排版，照片底部暂时被覆盖，结束后恢复。全屏模式独立安排角色和多行文字。唤醒录音显示停顿发送提示，按键录音显示松开发送提示。

对应 NVS 键为 `cloud-ai/disp_light`（亮度和来源合并保存）、`cloud-ai/disp_voice`（按键与唤醒的两个独立位）、`cloud-ai/disp_expr`（48 个稳定 ID 的启用位）、`cloud-ai/disp_body`（是否启用竖屏全身角色，默认关闭）；默认值不改变原有屏型、方向、待机页或照片数据。亮度设置不修改 PSRAM 中的照片像素，反复调暗/调亮不会累积画质损失。表情库接口 `/display/expressions`（GET/POST）、`/display/expressions/image`（GET）、`/display/expressions/preview`（POST）以及造型设置 `/display/appearance`（POST）均要求已登录；非法选择或全停用返回 422，设备忙时拒绝修改/预览。

## 扫码进入初始化配置

设备未保存 Wi-Fi、联网失败或空闲时长按中断键 5 秒，都会进入现有配置热点流程：

1. 屏幕显示 **“1 连接热点”**，用手机系统相机扫描 Wi-Fi 二维码，确认加入 `ROBOT-xxxx`。也可手动选择热点，密码 `12345678`。
2. 检测到热点有客户端连接后，屏幕切换为 **“2 打开配置页”**。若手机没有自动弹出配置入口，再扫一次网址码，进入 `http://192.168.4.1/setup`。
3. 输入设备连接码（首次默认 `123456`，修改过则使用新码），直接进入 Wi-Fi 设置。保存家庭 Wi-Fi 后，到“设备与更新”补齐设备凭证。
4. 家庭 Wi-Fi 连通后，热点按原有流程延迟关闭。手机切回同一家庭 Wi-Fi，用屏幕顶部的新 IP 继续访问后台。

Wi-Fi 码采用 [ZXing 记录的 Wi-Fi 二维码格式](https://github.com/zxing/zxing/wiki/Barcode-Contents#wi-fi-network-config-android-ios-11)，连接热点与打开网页是两个动作，是否自动弹出网页取决于手机系统；单个网址码不能让未联网的手机直接访问设备。二维码只含配置热点信息或本地网址，不包含设备 Token、连接码或家庭 Wi-Fi 密码。配网时有效亮度最低暂时提高到 30%，退出后恢复原设置；页面的登录保护不变。

二维码复用 Arduino-ESP32 3.3.11 随附的 Espressif `qrcode` 组件，不需要另装二维码库。两张码只在内容变化时编码并缓存模块，按整数倍绘制并保留四个模块宽的白边。

本次已使用 ESP32-S3 / ESP SR 16M / OPI PSRAM 配置编译，并运行生产绘制代码的主机检查：两种屏幕四个方向共 192 次场景绘制、48 组表情选择/保存/预览恢复、96 张不同造型缩略图、亮度与 NVS 写入失败处理、四种按键/唤醒显示组合、照片恢复及 16 张二维码截图解码。手机/桌面浏览器检查了分类、搜索、批量选择、表单字段、预览错误反馈与布局。主机检查复用实际 Adafruit/U8g2 绘制库，硬件及二维码编码入口使用替身；浏览器使用本地夹具，不能替代实物测试。检查程序在 [`tests/display_host`](tests/display_host/README.md)。2026-09-29 已写入 COM3 并确认启动、联网、屏幕就绪及离线唤醒就绪，详见 [`tests/FIX_VERIFICATION.md`](tests/FIX_VERIFICATION.md)；背光/旋钮响应、录音同时显示时的流畅度、手机相机识别和热点自动弹页仍待实机确认。参考图中的音乐播放器和充电识别尚未接入对应数据源，本次未新增这些功能。

## 四路 SG90 舵机（简单角度控制）

新增 `robot_servos.h/.cpp`，使用 ESP32-S3 自带的 LEDC 硬件 PWM，无需安装舵机库。上电直接输出以下默认位置并持续保持，没有自动往复、运动轨迹或缓动：

| 舵机 | 信号 GPIO | 上电默认角度 |
| --- | --- | --- |
| 1 号 | 12 | 0° |
| 2 号 | 13 | 0° |
| 3 号 | 14 | 180° |
| 4 号 | 17 | 180° |

串口监视器使用 `460800` 波特率和新行结束符，**每次发送一条命令**：

```text
/servo
/servo 1 90
/servo all 90 90 90 90
/servo home
/servo off
```

分别表示查看状态、1 号转到 90°、四路转到 90°、恢复 `0/0/180/180`、关闭四路 PWM。`/servo on` 同样恢复默认位置；关闭后发送单路角度命令只重新启用该路。角度必须是 `0..180` 的整数，参数错误整条命令不执行。以上命令在主循环空闲时处理；对话中的阻塞录音/网络操作可能延后串口响应。2026-10-02 新增默认关闭的回应小动作和网页校准/预览，见 [陪伴功能说明](COMPANION_FEATURES.md)。

默认角度在 `robot_servos.h` 的 `DEFAULT_ANGLES` 中修改，引脚在 `hardware_pins.h` 中修改。PWM 为 50 Hz，暂用 `500..2500 µs` 对应指令 `0..180°`；SG90 的不同批次需要按实物校准 `MIN_PULSE_US` / `MAX_PULSE_US`。串口显示的是指令角度，没有位置反馈，不代表已测得的实际角度。首次上电先不安装连杆负载；若到端点持续嗡鸣、顶住或发热，应断电并收窄脉宽范围。舵机需要独立的合适电源，并与 ESP32 共地，不能由 ESP32 的 3V3 供电，详见接线文档。

OTA 检查/安装开始前关闭 PWM，检查结束后可用 `/servo home` 恢复；实际重启后会重新输出默认位置。`off` 只是关闭控制脉冲，不是物理断电或机械制动。

## ST7789 布局、后台登录和多 Wi-Fi

当前 ST7789 / M200T 保持原生横屏 `320×240`，默认屏幕型号保持为 ST7789。除全屏照片外，顶部固定显示局域网 IP；配网时显示配置热点 IP。主界面包含机器人、时间/日期、当前天气和下一闹钟，过长地区名称在限定区域内滚动；三天天气按列显示图标和温度范围；便签页显示最近内容及未完成待办数量。ST7735S 仍使用单独的 `160×128` 布局。

后台“屏幕旋转方向”可选择 `0° / 90° / 180° / 270°`，按屏幕原生竖屏计算：0° 和 180° 为竖屏，90° 和 270° 为横屏，默认 90° 与原来的方向相同。保存新方向后约 2 秒自动重启，方向保存在 NVS，普通重启和应用 OTA 不会重置。ST7789 竖屏为 `240×320`，ST7735S 竖屏为 `128×160`；竖屏主界面独立排版，三天预报改为三行。显示照片时隐藏顶部状态栏；其他页面完整显示 IP，小屏竖屏时省略电池图标以留足空间。旋转不增加帧缓冲内存。

新增独立随机表情页和图片页。后台“待机页面显示”可勾选五类页面，多选自动轮播，单选固定显示；表情页固定显示时仍会随机更换表情。已有设备保留原来的页面选择，需要在后台勾选新增页面；没有保存过选择的新设备默认启用表情、主界面、预报和便签。文字使用透明绘制，取消文字区域的独立色块；时间使用对应尺寸的字形，避免放大小号点阵字。屏幕实际像素数不变，中文仍受现有字库覆盖范围限制。

照片使用方式：登录后台，在“屏幕与相册 → 添加图片”选择 JPG、PNG 或 WebP（每张最多 8 MB、2400 万像素）。点击各文件名，在预览中拖动定位、通过滑块缩放 100%–400%，或使用方向键微调；“居中重置”恢复默认裁剪。每张图片单独保留本次选择期间的裁剪位置，调整好后统一上传。裁剪框固定为当前屏幕比例，不拉伸、不留边；照片页隐藏顶部 IP，其他页面保留 IP。屏幕方向改变后需重新预览。

相册最多保存 8 张照片，新上传会添加到空位，相册满时拒绝上传而不覆盖旧图；可逐张显示、预览或删除。切换屏幕方向后，已保存图片会居中裁剪铺满新方向。设备只保存最终裁剪图；如需重新选择原图其他区域，须再次选择原始文件。兼容旧版图片文件，但旧图可能已经带有留边像素，后台会提示重新上传原图。照片与便签共用现有文件系统，普通重启和同分区的应用 OTA 会保留，格式化或更换分区不会保留。

裁剪、缩放和转换全部在浏览器完成，设备接收固定尺寸 RGB565，不增加设备帧缓冲或 JPEG/PNG 解码库。ST7789 图片横屏为 `320×240`、竖屏为 `240×320`，文件为 153,608 字节（150 KiB 加 8 字节头）；ST7735S 横屏为 `160×128`、竖屏为 `128×160`，文件为 40,968 字节。上传分块写入临时文件并校验后保存，失败保留已有图片。显示复用现有 PSRAM 帧缓冲及至多 640 字节行缓冲。放大裁剪会减少保留的原图像素，低分辨率照片放大过多可能变模糊。

文字透明背景修复：当前 U8g2_for_Adafruit_GFX 在 `setFont()` 切换字体时会将透明标志清零。所有字体切换统一经过 `setTransparentFont()`，先换字体再设置透明模式，消除时间、中文和状态文字覆盖波浪背景时的深色字框。主机检查在渐变底图上验证字体切换后只有前景笔画像素变化。

相册功能此前检查包含 C++ 源码结构、嵌入脚本语法、四种图片尺寸的实际 JavaScript 编码/预览/上传数据一致性，以及本地浏览器的选图预览和上传。当前显示改动的编译与主机验证见上方说明。最新版本已写入实机，后台裁剪控件及原有 4 张照片保留已确认；实体屏幕最终观感仍需确认。实机请依次确认四个方向的 IP/文字边界、五类待机页、长地区滚动、图片上传与删除、重启保留图片和方向，尤其检查 ST7735S 小屏的实际字形效果。

内存处理保持单个 150 KiB 的 ST7789 帧缓冲位于 PSRAM，内部 RAM 只保留 640 字节扫描行；没有新增全屏缓冲。绘制文字改用 160 字节行缓冲，避免逐字符创建临时 `String`；显示模型只在内容变化时复制。后台 HTML 改为分段发送，取消原来整页约 28 KB 的连续 `String` 预分配。扫描结果最多缓存 20 条并释放 Wi-Fi 库的原始扫描结果，保存网络最多 5 组，会话最多 4 个；这些应用缓存合计约 1.5 KiB，不包含 Wi-Fi 库扫描期间的临时内存。

后台使用方式：

1. 浏览器访问屏幕顶部的 IP，输入一次设备连接码登录（首次默认 `123456`）。之后保存设置、天气搜索、闹钟、便签和 OTA 操作都使用当前会话，不再逐项输入密码。
2. 会话保存在浏览器 HttpOnly Cookie 和设备 RAM 中；8 小时无访问、退出登录、设备重启或修改连接码后需要重新登录。换 IP/浏览器也需在新地址登录。连续输错 5 次锁定 60 秒。
3. “Wi-Fi 网络”区域进入后自动扫描，点选网络、输入密码并点击“保存并连接”。已保存网络留空密码会复用原密码；开放网络需勾选“这是无密码网络”。可手动输入隐藏 SSID。
4. 最多保留 5 组 SSID/密码，重启和断电后保留；保存第 6 组替换最早保存的网络，也可以点击“忘记”。旧版单组 Wi-Fi 自动迁移一次。密码不会通过网页状态接口返回。
5. 开机或断线后的重试先重新扫描，只从实际扫描到的已保存网络中按信号强度选择；手动保存的网络也必须可见，才会优先连接。不再盲试未出现的历史网络，隐藏 SSID 需先在路由器开启名称广播。每个候选最多等候 15 秒，明确失败会提前结束并断开。没有匹配网络时立即进入配置热点；热点期间每 60 秒重新扫描。关闭驱动对上一个 SSID 的自动重连，由上述扫描流程统一选择。已连接时不主动切换。

扫描和连接等待期间继续处理网页及配网 DNS 请求，网络修改暂时返回忙碌提示。网页列表最多显示信号最强的 20 个网络；自动连接另行保留扫描到的最多 5 个已保存网络，因此弱信号的已保存网络不会因网页列表截断而遗漏。扫描失败、取消或正在扫描时不复用过期的连接候选。相关主机回归检查见 [`tests/wifi_host`](tests/wifi_host/README.md)。

设备凭证、音量等设置与 Wi-Fi 保存分开；修改普通设置不再强制重连 Wi-Fi。网页状态、会话记录和写操作均要求已登录，仅健康检查和配网探测入口保留公开访问。

## 低音量调节

文件和流式语音直接在 32 位 I2S 输出上缩放，避免先缩到 16 位时把很小的样本截成零。网页固定音量使用平方根增益，`0` 静音，`100` 保持原始最大幅度；例如 `1/10/25/100` 对应约 `10%/31.6%/50%/100%` 的数字幅度。提示音保持原来的限幅。

针对“电位器半圈左右就没声音”，电位器路径直接使用完整的 12 位 ADC 读数和立方根低段补偿，不再先取整到 `0..100` 再计算增益。10% 的 ADC 输入约得到 46% 的输出幅度，适用于低半程读数很小的音频型旋钮。`voice_input.cpp` 的 `POT_ADC_MIN/MAX` 可校准实际端点；`POT_RESPONSE_EXPONENT` 默认 `1/3`，若线性旋钮低段过灵敏，可改为 `0.5` 或 `1.0`。平滑滤波仍保留，真实零端点为静音。

串口发送 `/volume` 可查看当前音量模式、GPIO1 原始 ADC 与滤波 ADC。将旋钮分别转到最小、中间、最大后各读一次：如果低半圈的原始 ADC 始终为 0，软件曲线无法恢复不存在的输入，需要检查电位器两端是否接 3V3/GND、滑臂是否接 GPIO1，不能接 5V；若原始 ADC 有变化而听感仍不合适，再调整上述曲线。使用旋钮时后台音量模式应选“GPIO1 电位器”。

这是对数字音量路径的修正，实际低音量可听范围仍取决于音源、功放和喇叭，需烧录后试听。若实体电位器仍在行程前段无变化，还需检查电位器类型和 ADC 接线。当前修改按要求未完成固件编译或实机验证，请在原来的 ESP SR 16M / OPI PSRAM 配置下自行编译。

## 首次烧录的关键点

不要在项目目录放置 `partitions.csv`，必须在 Arduino IDE 的 Tools 菜单明确选择 `ESP SR 16M`。项目保留 [`partitions.esp_sr_16.csv`](partitions.esp_sr_16.csv) 只用于核对布局；它故意不叫 `partitions.csv`，避免再次出现“分区表被覆盖、但上传命令没有写模型”的隐蔽错误。该方案把 16 MB Flash 分成两个各 3 MB 的应用槽：

- `app0`：当前运行固件；
- `app1`：线上更新写入的备用槽；
- `spiffs`：6 MB，用于录音、便签和设备对话记录；
- `model`：3.9 MB，保存 13 个中文 WakeNet9 离线唤醒模型；
- NVS：继续保存 Wi-Fi、设备 ID、Token 和语音配置。

Arduino IDE 选择：

- Board：ESP32S3 Dev Module
- USB Mode：Hardware CDC and JTAG
- USB CDC On Boot：Disabled
- Flash Size：16MB
- Partition Scheme：ESP SR 16M (3MB APP/6MB SPIFFS/3.9MB MODEL)
- PSRAM：OPI PSRAM
- Erase All Flash Before Sketch Upload：Disabled

Arduino CLI 对应 FQBN：

```powershell
$fqbn = 'esp32:esp32:esp32s3:USBMode=hwcdc,CDCOnBoot=default,FlashSize=16M,PartitionScheme=esp_sr_16,PSRAM=opi'
arduino-cli compile --fqbn $fqbn .\esp32_cloud_ota_device
arduino-cli upload --fqbn $fqbn -p COM3 .\esp32_cloud_ota_device
```

`CDCOnBoot=default` 会关闭启动时的 USB CDC，把 `Serial` 固定到 UART0；当前外接 USB 转串口因此统一使用 COM3，波特率为 460800。若以后改回 ESP32-S3 原生 USB 口调试，需要同时把该选项改为 `CDCOnBoot=cdc` 并重新编译。

`1.3.x → 1.4.1` 会把原 9.9 MB FATFS 改为 6 MB SPIFFS，并增加模型分区，因此第一次安装 1.4.1 必须通过 USB 完成，不能把 1.4.1 当作普通应用 OTA 推给 1.3.x。首次挂载会格式化新的 SPIFFS，旧文件系统中的便签、待办和对话历史不会保留；NVS 中的 Wi-Fi、Token、连接码和闹钟仍保留。安装 1.4.1 后，后续保持相同分区表的 1.4.x/1.5.x 应用固件可以继续 OTA。

编译完成后、点击上传前，可运行只读检查（不会访问 COM3）：

```powershell
.\esp32_cloud_ota_device\verify_offline_wake_build.ps1
```

只有输出“离线唤醒构建检查通过”，并明确显示 `模型写入：0xC10000 srmodels.bin`，才应点击上传。

3.3.12 生成的 `flash_args` 和 `.merged.bin` 不包含中文模型；完整上传应使用 Arduino IDE/CLI 的上传流程，其 `upload.extra_flags` 会写入模型。检查脚本会核对当前开发板包的实际上传配置，不会把缺少模型的 `flash_args` 当作完整首刷命令。

若不在 `secrets.h` 预置凭证，首次启动会自动开启 `ROBOT-xxxx` 配置热点，固定密码为 `12345678`。手机连接后通常会自动弹出后台入口；也可以手动打开 `http://192.168.4.1/`，先输入设备连接码登录，再扫描选择 Wi-Fi、填写密码并保存连接。设备 ID、Token 在设备与语音设置区域单独保存。目标 Wi-Fi 连接成功后热点延迟 15 秒关闭；失败时热点保持开启并每 60 秒重试。运行中 Wi-Fi 断开超过 30 秒也会自动开启热点；设备空闲时长按中断键 5 秒可手动进入配网。固件不再初始化或广播 BLE。仍可复制 `secrets.example.h` 为 `secrets.h` 预置凭证；该文件已由仓库规则排除。

高德 Key 必须是“Web 服务 API”类型。可以在受 Git 忽略的 `secrets.h` 中设置 `AMAP_PROVISIONED_WEB_KEY` 完成首次写入，也可以在设备网页输入；固件只把 Key 保存到 NVS，网页和状态 JSON 均不回显明文。天气接口按高德要求使用 `adcode`，地址搜索和 IP 定位只通过设备代理调用，浏览器不会取得 Key。

天气与 AI 的日志分为两级，排查时不要混淆：

- `weather_context_ready`：ESP32 已取得高德实况和未来三天预报，只表示设备本地缓存可用。
- `weather_context_accepted`：创建云端对话任务时，服务器返回 `context.schema=1`、`context.weather=true`，表示天气已真正进入本轮 AI 上下文。
- `weather_context_unconfirmed`：当前服务器仍是旧版或未接收天气字段；录音对话可以继续，但天气回答不可信，应先更新云端服务，不需要反复修改 Wi-Fi 或高德 Key。

询问“今天天气怎么样”时，正常顺序应为 `weather_context_ready`（通常启动后出现一次）、`uploading`、`weather_context_accepted`、`waiting_segment`。云端收到有效天气后会直接依据设备提交的数据回答，不再回复“无法查询实时天气”或让用户另行查看网页。

网页“语音与音量 → AI 对话设置”可读取和保存本设备的回答风格、角色设定、记忆轮数与联网搜索开关，并展示系统提示词及内置规则。联网搜索默认关闭，设置按设备保存在服务器；只控制 AI 额外搜索，不关闭 Wi-Fi 或服务器语音处理。明确的本地天气、便签待办查询、北京时间日期和两数简单算术由服务器按已知数据或规则直接回答，不调用语言模型；跨城市、过期、缺失或复杂问题才回到模型，搜索仍受设备开关控制。网页首页“历史记录”可勾选确认后手动清空本机聊天记录，并可单独选择同时清空本设备的服务器记忆；照片、提醒和计费记录不受影响。

服务器“服务设置”中的识别、合成各自支持本地主用或云端主用及回退方案。本地 ASR／TTS、服务器本地语言模型和外部聊天 API 是三种独立配置；百炼语音使用独立 WSS 接口，不是 OpenAI 兼容聊天地址。当前设备源码仍为待手动编译上传的 1.4.3，未发布新 OTA 包。

闹钟和计时器保存在独立 NVS 命名空间，普通重启、OTA 和断电都不会丢失。可在设备网页查看、添加和删除，也可说“每天早上七点设置闹钟”“十分钟后提醒我”“取消下一个闹钟”或“查看所有闹钟”。提醒响起时按说话键延后 5 分钟，按中断键关闭。设备断电期间不能响铃；恢复供电并完成 NTP 同步后，24 小时内错过的单次提醒会补响。

便签和待办保存在文件系统的 `/memos.json`，普通重启、断电和应用 OTA 后继续保留；总数最多 20 条，单条最多 180 个 UTF-8 字节。设备网页可添加、完成、恢复、删除和批量清理，也可说“记一下明天买电池”“添加待办检查屏幕接线”“查看所有待办”“完成第 2 个待办”或“删除第 1 条便签”。

也可以在 Arduino 串口监视器中使用 COM 口配置。波特率选择 `460800`，行结束符选择“新行”或“Both NL & CR”，然后发送：

```text
/config {"ssid":"BELL_3\u53f7","wifi_password":"你的密码","connect":true}
```

命令全是 ASCII，ArduinoJson 会把 `\u53f7` 还原为 Wi-Fi 名称中的“号”。真实命令保存在受 Git 忽略的 `serial_config_command.local.txt`，可直接复制粘贴。输入 `/help` 可查看其他串口命令。

设备连接码首次默认为 `123456`，写入 NVS 后不会因重启或重新初始化而随机变化。进入后台时登录一次；可在登录后的设置页修改连接码，新码立即生效并使旧会话失效。热点密码固定为 `12345678`，与设备连接码相互独立。登录连续 5 次输入错误后锁定 60 秒。

## OTA 行为

设备不会在启动后自动检查 OTA。仅在手动请求或每天凌晨 03:00～03:09 的窗口内检查一次；默认凌晨只检查不安装，在设备网页选择“凌晨自动更新”后才会自动安装。网页还可以只检查、立即安装，或把当前可用版本标记为“暂不更新”；结果页会在设备恢复响应后自动返回主页，TFT 在检查完成后回到待机界面。暂缓状态保存在 NVS，更高版本不受影响。也可以使用：

- 串口命令 `/ota-check`（只检查）或 `/ota`（确认安装）；
- 设备网页中的更新控制区。

OTA 使用独立连接，强制 HTTPS，不使用语音链路的 HTTP 回退。请求携带现有 `X-Device-ID` 和 Bearer Token。下载开始前会释放 I2S/DMA，按 4 KiB 流式写入非运行分区，不把整个固件放入内存。

设备要求服务器实现：

```text
GET /voice-api/v1/firmware/manifest
```

服务器没有更新时返回 `204` 或 `304`；有更新时返回：

```json
{
  "version": "1.0.1",
  "hardware": "esp32s3-cloud-voice-v1",
  "size": 2100000,
  "sha256": "64位小写十六进制",
  "url": "https://voice.bsnlch.xyz/voice-api/v1/firmware/download/1.0.1",
  "signature": "RSA-SHA256签名的Base64",
  "force": false
}
```

签名原文必须逐字节为以下六行，最后一行后没有换行；`force` 必须是小写 `true` 或 `false`：

```text
version
hardware
size
sha256
url
force
```

固件会先用烧录进设备的 RSA 公钥验证清单，再下载固件并计算 SHA-256；两项都通过才激活备用分区。下载地址必须是 HTTPS，而且必须与 manifest 接口同源，防止设备 Token 被发送到其他主机。

## 发布下一版

每个版本必须存放在独立的 `releases/主.次.修订/` 目录中，已存在的版本禁止覆盖或复用。归档内容包括固件、签名清单、OTA ZIP、构建选项、发布元数据和不含密钥的源码快照。

1. 修改 `esp32_cloud_ota_device.ino` 中的 `FIRMWARE_VERSION`，必须使用从未发布过的 `主.次.修订` 三段数字。
2. 使用与首刷相同的 FQBN 编译，确认 `.bin` 不超过 3 MB。Arduino IDE 编译后保留其临时构建目录中的 `build.options.json`。
3. 使用不可覆盖的归档脚本检查构建选项、复制源码快照并生成签名包：

```powershell
.\esp32_cloud_ota_device\archive_release.ps1 `
  -Version 1.4.2 `
  -FirmwareBin "$env:LOCALAPPDATA\arduino\sketches\构建目录\esp32_cloud_ota_device.ino.bin" `
  -BuildOptionsJson "$env:LOCALAPPDATA\arduino\sketches\构建目录\build.options.json"
```

脚本强制要求 `CDCOnBoot=default`、`PSRAM=opi`、16 MB Flash，以及 `ESP SR 16M (3MB APP/6MB SPIFFS/3.9MB MODEL)` 分区，并拒绝 `EraseFlash=all`。归档元数据同时记录固件、参考分区表和中文模型包的 SHA-256。若目标版本目录已经存在，脚本直接失败，必须增加版本号。

4. 登录云服务器 `/admin/firmware`，上传该版本目录内的 `esp32-ota-版本.zip`，填写更新说明及最低来源版本（1.4.2 为 1.4.1）。服务器会再次核对硬件通道、版本、HTTPS 下载地址、镜像大小、SHA-256 和 RSA 签名，同一版本不能覆盖。

匹配的私钥位于 `ota_release_private/firmware_signing_private.pem`，目录内规则禁止 Git 跟踪。请现在就离线备份；丢失私钥后，已经首刷的设备将无法接受新的签名清单。不要把私钥上传到 ESP32、Git、公开服务器目录或固件下载目录。

## 便签、待办和提醒执行

ESP32 实体屏幕的便签页按类型显示：便签和待办都有时左右两个圆角窗口，只有一类时显示一个满宽窗口，两类都空时显示空状态。标题标明各类条数；待办有已完成标记，长中文按各自窗口宽度换行并自动翻页。保留最近四条/类的展示范围，已有存储数据不变，适配 ST7789/ST7735 横竖屏及底部语音条。

支持“添加待办检查屏幕接线”“一会儿需要去买东西，加个待办”和“明天早上 9:35 提醒我做其他事情，加一个待办”。最后一种明确的复合指令分别保存待办与提醒，回应包含各自实际执行结果；只添加待办不会自动设置闹钟。设备时钟未同步或保存失败时，不会确认提醒已设置。便签中的“删除所有闹钟”等文字只作为便签内容保存。

设备网页以左右标签分页显示便签和待办，每类列表独立编号，与语音“完成第 2 个待办”等操作一致。待办支持完成、恢复和删除；批量清理需要确认。已有提醒和便签的存储格式不变。

新固件上传语音时声明 `X-Device-Local-Control: 1`，在识别后向服务器回传本地执行结果。服务器根据设备回执播报，不再让语言模型猜测操作是否成功；回执超时不播报成功。该功能需配套服务器接口，新服务器仍兼容未声明此能力的旧固件。

主机回归测试位于 `tests/reminder_host`，不替代 ESP32 编译、收音和闹钟实机验证。本次尚未发布设备 OTA 包。

## 当前边界

设备网页“语音与音量”提供“本设备 API 用量与费用”，手动读取近 24 小时、7 天、30 天或累计统计，不增加实体屏幕页面。服务器保存和计算统计，设备通过 `/voice-api/v1/device-usage?view=compact` 按需转发精简数据，流式传输、不解析整包 JSON、不写入文件或 NVS、不定时后台查询。仅显示本设备的 API 凭证指纹、模型用途、成功/失败、Token/语音发送量。金额只显示人民币，服务器用 Decimal 四舍五入保留两位小数；语言模型和云端语音分别合计，总额按原始金额相加后舍入。非人民币费用不换算、不混入合计；未计价或不完整费用明确标注。服务器账本仍保留原始精度和币种。余额、赠送额度及实际扣费以厂商账单为准。此入口需要升级设备固件，本轮仍未编译或发布设备 OTA。

已有版本目录保持不可覆盖；已验证的 `1.3.0` 保存在独立目录，失败的 `1.4.0` 保留拒绝记录；现存归档中没有 `1.4.1` 的签名包，不能补造同名包。首次安装新布局必须通过 USB 写入新的分区表、应用和模型包；已运行 `1.4.1` 的设备可以应用 OTA 到同一布局的 `1.4.2`。本轮不执行设备 USB 烧录，实机收音效果仍需升级后验证。
