# 2026-09-29 设备修复验证

当前固件已写入 COM3 的 ESP32-S3，esptool 写入后哈希校验通过。硬件为 16 MB Flash、8 MB OPI PSRAM；使用 Arduino ESP32 3.3.12、ESP SR 16M 分区。

## 修复及证据

- 编译体积：已知的 13 个模型全部为 WakeNet9，直接选择对应接口，避免通用选择器链接不使用的 WakeNet10。最终 Sketch 为 2,203,446 / 3,145,728 字节（70%），静态 RAM 为 66,180 字节（20%），应用 bin 为 2,203,600 字节。构建校验同时检查 16 MB 启动头、OPI PSRAM、分区和中文模型包哈希。
- 启动空屏：此前启动头声明 4 MB，无法容纳 ESP SR 16M 分区。已按实物容量修正并写入启动文件。最新应用更新后 HTTP 报告 display_ready=true，实际配置为 ST7789、320×240。
- Wi-Fi：连接前独立扫描，仅尝试扫描到的已保存网络，按信号排序；关闭驱动自动重连，扫描失败或没有匹配时不盲试历史 SSID。实机日志显示 3 个已保存网络中仅 1 个可见并成功连接；最终状态 wifi=connected。主机回归覆盖扫描失败、取消、空结果、缓存、弱信号匹配及删除配置。
- 字体黑块：U8g2 切换字体会重置透明模式，现每次设置字体后恢复透明绘制。使用实际 Adafruit/U8g2 绘制库在非均匀背景上验证，字形外像素保持原背景；两种面板、四个方向的主机绘制检查通过。实体屏幕的最终观感仍需用户确认。
- 照片裁剪：浏览器支持拖动、100%–400% 缩放、方向键微调、居中重置及各图片独立裁剪。浏览器夹具验证两张预览与上传 RGB565 的 SHA-256 一致，390px 手机布局无横向溢出，并覆盖四种目标尺寸的边界。实机后台已返回新裁剪控件，原有 4 张照片仍保留，相册容量为 8。未向实机上传测试照片。
- 最终设备状态：屏幕、离线唤醒和时钟就绪，busy=false，last_error 为空；串口 Health: ok，天气更新成功。

## 使用及限制

刷新设备后台，在“屏幕与相册 → 添加图片”中逐张调整后上传。设备仅保存最终裁剪图，再次裁剪其他区域需要重新选择原图。固定尺寸输出不会因放大增加单张设备存储或显示内存；过度放大可能降低清晰度。

本次没有验证真实按钮录音时的流畅度、旋钮亮度、手机扫码与热点自动弹页，也没有实现参考图中尚未接入数据源的音乐播放器或充电识别。
